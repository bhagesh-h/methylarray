# bhagesh-h/methylarray: Output

## Introduction

This document describes the output produced by the pipeline. Most of the plots are taken from the MultiQC report, which summarises results at the end of the pipeline.

The directories listed below will be created in the results directory after the pipeline has finished. All paths are relative to the top-level results directory.

## Pipeline overview

- [Preprocessing](#preprocessing): one HDF5-backed SummarizedExperiment with the preprocessed arrays
- [Sample QC](#sample-qc): per-array QC statistics with the sample metadata
- [Reference resources](#reference-resources): the sesameData cache, when `--save_reference` is set
- [MultiQC](#multiqc): report with the sample QC table and software versions
- [Pipeline information](#pipeline-information): execution reports and parameters

### Preprocessing

- `preprocessing/sesame/sesame_se/`
  - `assays.h5`: the assays, stored on disk.
  - `se.rds`: the SummarizedExperiment that refers to `assays.h5` by a relative path.

Load the directory in R, wherever it has been copied to:

```r
se <- HDF5Array::loadHDF5SummarizedExperiment("preprocessing/sesame/sesame_se")
```

Rows are probes (EPIC v2 probe IDs such as `cg00000029_TC21`; `rowData(se)$cpg_id` holds the CpG name without the suffix) and columns are arrays, sorted by sample name. Arrays marked `exclude` in the samplesheet are not included. Assays:

| Assay            | Content                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `beta`           | Beta values after `prepSesame` (default `QCDPB`); probes failing the quality mask, pOOBAH detection or the bead count are `NA` |
| `beta_unmasked`  | The same beta values without masking, for methods that need complete data                                                      |
| `detp`           | pOOBAH detection p-values, computed on the signal after the steps before `P`                                                   |
| `meth`, `unmeth` | Methylated and unmethylated intensities after preprocessing                                                                    |

`colData(se)` holds the samplesheet metadata and the QC statistics described below. `metadata(se)` records the platform, the preprocessing method, the `prepSesame` code and the SeSAMe version.

### Sample QC

- `qc/sesame/sesame_qc.tsv`: one row per array with the samplesheet metadata (`sample`, Sentrix ID, position, row and column, plate, well, batch, reported sex and age, replicate group) followed by:
  - `platform`, `prep`: detected platform and the `prepSesame` code used
  - `predicted_sex`: sex predicted by SeSAMe `inferSex`
  - `num_masked`, `frac_masked`: probes set to `NA` in `beta`
  - the SeSAMe QC statistics from `sesameQC_calcStats` on the raw signal: detection (`frac_dt`, by probe type), intensity (`mean_intensity`, in-band and out-of-band means), channel and dye bias (`RGratio`, `RGdistort`, Infinium I channel switches) and the beta distribution (`mean_beta`, `frac_meth`, `frac_unmeth`, `frac_na`)

### Reference resources

- `references/` (only with `--save_reference`)
  - `sesame_cache/`: ExperimentHub cache with the sesameData resources for the platform. Pass it to `--sesame_cache` to run without network access.
  - `sesame_resources.tsv`: title, ExperimentHub ID, cached file and MD5 checksum of each resource.

### MultiQC

- `multiqc/`
  - `multiqc_report.html`: a standalone HTML file that can be viewed in your web browser.
  - `multiqc_data/`: directory containing parsed statistics from the different tools used in the pipeline.
  - `multiqc_plots/`: directory containing static images from the report in various formats.

[MultiQC](http://multiqc.info) is a visualization tool that generates a single HTML report summarising all samples in your project. Most of the pipeline QC results are visualised in the report and further statistics are available in the report data directory.

The general statistics table shows, for every array, the percentage of detected and masked probes, the mean intensity, the red/green ratio and the predicted sex. The report also lists the software versions of every step and a methods description with references. For more information about how to use MultiQC reports, see <http://multiqc.info>.

### Pipeline information

- `pipeline_info/`
  - Reports generated by Nextflow: `execution_report.html`, `execution_timeline.html`, `execution_trace.txt` and `pipeline_dag.dot`/`pipeline_dag.svg`.
  - Reports generated by the pipeline: `pipeline_report.html`, `pipeline_report.txt` and `software_versions.yml`. The `pipeline_report*` files will only be present if the `--email` / `--email_on_fail` parameter's are used when running the pipeline.
  - Parameters used by the pipeline run: `params.json`.

[Nextflow](https://docs.seqera.io/platform-cloud/reports/overview) provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
